Security

安全与校验

先校验，再运行；把能防的和防不了的分开说清楚。

🔍 可验证

每个安装包都能用 SHA256 核对，发版说明里附校验值，页面提供在线校验工具。

🚫 无遥测

程序与网站都不上报使用数据；没有账号体系、没有崩溃上报、没有第三方统计。

🏠 数据在你自己手里

云盘是自建服务，文件存在你自己的服务器上；WebDAV 让任何备份工具都能直接接。

先校验，再运行

下载完成后的第一件事不是双击，而是算一次哈希。Windows 自带命令就够：

certutil -hashfile 文件名 SHA256

Linux / macOS：shasum -a 256 文件名。结果应与 Release 说明里公布的值逐字一致。

没有终端也能做：在线 SHA 工具 在本机计算，文件不上传。

威胁模型：我们防什么，不防什么

✅ 能防的

  • 下载过程中被劫持改写（SHA256 对不上）
  • 伪装成同名的第三方镜像（只认官方 Releases 与文档里列出的地址）
  • 页面被注入脚本（站点是纯静态，动态数据一律用 textContent 渲染）

⚠️ 防不了的

  • 没有代码签名证书 —— 无法从系统层面证明「这个 exe 是谁做的」
  • 你的系统本身已被入侵
  • 你在非官方渠道拿到的「修改版 / 汉化版 / 破解版」

所以：哈希对上，只证明这个文件和作者发布的一致。

隐私边界说清楚

  • 网站：静态托管在 GitHub Pages，服务器访问日志由 GitHub 记录，我们拿不到也不收集。
  • 页面请求：只有 api.github.com（读版本/状态）与你自己点开的站外链接。
  • 工具箱：139 个工具全部本地运算，输入不出浏览器；带缓存的页面（版本、状态）只存本地 localStorage，清缓存即消失。
  • 程序：无遥测、无后台上报。云盘连接地址由你自己填写。

发现安全问题怎么报

一般问题（死链、错字、样式）
直接 开 Issue 或提 PR 即可，公开讨论没问题。
安全问题（疑似后门、凭据泄漏、注入风险）
请不要在公开 Issue 里附利用细节。先在仓库开一个只写摘要的 Issue 说明「有安全问题，需要私下沟通渠道」，我们会在回复里约一个私下方式。修好之后再公开细节。
发版方的自查清单
每次发版：① 资产文件名与下载页 data-asset 一致；② Release 说明里附每个资产的 SHA256；③ 公开 SHA256SUMS.txt；④ 打 tag 前跑一遍 CI。详见 校验与验证。
