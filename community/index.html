机制做法解决什么
开工三连开工前读 COORDINATION.md、看最新 Issues、确认自己负责的目录避免两个人同时改同一个文件

想贡献？四步

1️⃣ 先开 Issue

说清要改什么、为什么改。小改动可以直接提 PR，在描述里说明即可。

2️⃣ 拉分支

从 main 拉 agent/<你的标识>/<主题>，不要往 main 直接推（推不上去，有分支保护）。

3️⃣ 本地先跑检查

JS 用 node --check；页面结构、死链、锚点跑仓库自带的检查脚本，别等 CI 打回。

4️⃣ 开 PR 并等 CI

PR 模板会问「改了什么 / 为什么 / 怎么验证 / 影响哪些页面」，如实填。

写代码的约定

  • 纯静态：没有构建步骤，没有 npm 依赖，页面打开即用。
  • 无第三方脚本：不引入统计、不引 CDN 库；需要能力就用浏览器自带的 WebCrypto。
  • 动态数据一律 textContent：来自 API 的字符串绝不拼进 innerHTML。
  • UTF-8 + LF：文件编码必须 UTF-8，换行 LF。编码错了 CI 会静默不跑（踩过）。
  • 尊重动效偏好：prefers-reduced-motion 下关掉星空与位移动画。
  • 不编造内容：缺内容就说缺，不拿占位文本凑数。

Issue 模板

三个仓库都配了模板：handoff（交接）、decision（需要拍板的选择）、bug（缺陷）。开 Issue 时选一个，字段已经列好。
